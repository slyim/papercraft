# Craft source review

18 October 2026, Europe/Istanbul. Scope: current public source and documentation for the native Craft applications relevant to a local rectangle/text canvas. The source copies are ignored under `research/private/craft-source/`; no upstream code or assets were added to application code. This is a focused review, not a complete audit of those repositories.

**Observed in source:** these workspace package manifests declare `MIT OR Apache-2.0`, edition 2024, and egui/eframe 0.36 for frontend packages. PhotoCraft, VectorCraft, FigCraft, DesignCraft and craft-libs specify Rust 1.95; Launcher specifies 1.90. PaperCraft's egui/eframe 0.36.2 can use shared egui 0.36 controls without a major-version adapter. This version match alone does not prove behavior or backend compatibility: the reviewed Craft GUIs use wgpu, while PaperCraft uses glow.

**License boundary:** selecting the MIT option is compatible with PaperCraft's original MIT code, provided copied code retains the required copyright/license notices. Assets have separate terms. In particular, Launcher's [README license section](https://github.com/storytold/craft-launcher/blob/9cef5d2a0f207da50d31547a726057ea40f7e5b4/README.md#license) excludes ArtCraft's name, logo and mark from its source-code license. No Craft branding, font collection, icon set or application code is adopted here.

## Verified source conventions

### PhotoCraft

- **Model and selection:** `crates/doc/src/lib.rs` defines a layered image document, layer kinds, groups, masks and selection data; tiled pixel storage is shared through `Arc`. `crates/engine/src/lib.rs` keeps active/selected layers separately and restores targets through undo. This is a raster model, not a replacement for PaperCraft's node model.
- **Commands and history:** `crates/engine/src/commands.rs` registers command metadata. `Session::execute` in `crates/engine/src/lib.rs` is shared by UI and automation; an optional `coalesce` key merges consecutive edits into a single history step and is broken by other edits, undo or redo. `crates/ops/src/lib.rs` implements snapshot history with state and pixel-memory budgets. The [command-engine documentation](https://github.com/storytold/photocraft/blob/8d2e615ab93d424c4ec25ab15b4edb5368d1f9a6/book/src/architecture/command-engine.md) explicitly treats parameters and current state as untrusted inputs.
- **Transforms/rendering/persistence:** `crates/ui-egui/src/canvas.rs` owns document/view transforms and tool events. `crates/compose` provides CPU composition, `crates/gpu` the GPU path. `crates/format/src/lib.rs` and `autosave.rs` own `.pcraft` storage/recovery; these do not define PaperCraft files.
- **Export and automation:** the [SVG format guide](https://github.com/storytold/photocraft/blob/8d2e615ab93d424c4ec25ab15b4edb5368d1f9a6/book/src/formats/svg.md) documents SVG open/place, with text outlined and clip/mask/filter/image content rasterized; it explicitly states there is no SVG export. [Control protocol](https://github.com/storytold/photocraft/blob/8d2e615ab93d424c4ec25ab15b4edb5368d1f9a6/docs/control-protocol.md): an opt-in loopback JSON-lines server, authenticated once per connection with a token, plus CLI/MCP bridging and explicit automation file roots.
- **Accessibility:** the desktop enables eframe's AccessKit feature (`apps/photocraft/Cargo.toml`); custom controls provide `WidgetInfo`, with AccessKit role tests in `crates/ui-egui/src/shortcut_dispatch/tests.rs` and brush-panel tests. Screen-reader usability was not exercised in this review.

### VectorCraft

- **Model and selection:** `crates/doc/src/lib.rs` defines artboards, layer/object hierarchy, text, appearance and shared document nodes. `crates/doc/src/selection.rs` distinguishes object/point selections and filters noneditable targets. It is materially richer than PaperCraft's flat single-selection model.
- **Commands/history:** `crates/engine/src/lib.rs` has a common `Session::execute`, interaction begin/commit/cancel, grouped history, and rollback state for `command.batch`; implementations live in `crates/engine/src/cmd/`. The [architecture](https://github.com/storytold/vectorcraft/blob/cdba0aac03f83bbc633f5e2aa9500354648938d3/docs/architecture.md) describes tool preview/commit commands and structural-sharing snapshots. This supports copying the transaction convention, without importing the workspace's architecture into PaperCraft.
- **Transforms/rendering/persistence:** `crates/ui-egui/src/canvas.rs::Xf` centralizes point and delta conversions, including view rotation. The canvas rasterizes on workers through `crates/render`; `crates/format/src/lib.rs` and engine `cmd/fileio/` handle native files and atomic storage. Source-documented formats include SVG/PDF and raster export. Native `.vectorcraft` is not PaperCraft JSON.
- **Automation/accessibility:** [CLI main.rs](https://github.com/storytold/vectorcraft/blob/cdba0aac03f83bbc633f5e2aa9500354648938d3/apps/vectorcraft-cli/src/main.rs) implements `run`, `convert`, `info`, `commands`, `bench`, `perf`, `mcp`. [Control protocol](https://github.com/storytold/vectorcraft/blob/cdba0aac03f83bbc633f5e2aa9500354648938d3/docs/control-protocol.md) exposes commands, pointer/key injection, inspection, native screenshots and offscreen rendering, with bounded requests and automation roots; this port is unauthenticated and must be explicitly enabled. `apps/vectorcraft/Cargo.toml` has an optional `accessibility` feature; its existence does not establish that the installed build enables it.

### FigCraft

- **Model and selection:** `crates/doc/src/lib.rs` defines pages, a persistent node map, frame/group/shape/text kinds, components, variables, styles and prototype data. `crates/engine/src/lib.rs` records document, selected IDs and current page in each `HistoryEntry`; `ViewState` separately defines page/screen conversions and zoom. This separation prevents view changes from becoming document edits.
- **Commands/history:** the same engine implements `execute`, `begin_interaction`, `commit_interaction`, undo/redo and all-or-nothing `batch`, including references to earlier created IDs. The [CLI contract](https://github.com/storytold/figcraft/blob/d8ff1441b1cd47cb45f1e58b030409ef6f1e24bf/docs/cli.md) states that a whole `run` script is one undo step, failed batches roll back and no output file is written. Commands that need UI request dialogs; headless callers drop UI requests.
- **Rendering/persistence:** `crates/render` is the CPU pixel source for GUI/export; the frontend uses a render worker. `crates/format/src/lib.rs` documents versioned ZIP/JSON with embedded images and archive/decode limits, structural repairs and diagnostics. Current source has a best-effort `.fig` reader; the older architecture paragraph claiming none is stale. The current format source and CLI documentation take precedence.
- **Accessibility:** [a11y.rs](https://github.com/storytold/figcraft/blob/d8ff1441b1cd47cb45f1e58b030409ef6f1e24bf/crates/ui-egui/src/a11y.rs) provides names/roles/states for custom-painted controls, F6 region navigation, Tab within regions and arrow navigation through layers. Its tests exercise an active AccessKit tree; this is a concrete convention for later PaperCraft accessibility work, not a verified screen-reader result.
- **CLI/MCP/control:** `apps/figcraft-cli/src/main.rs`, `crates/mcp`, and [control protocol](https://github.com/storytold/figcraft/blob/d8ff1441b1cd47cb45f1e58b030409ef6f1e24bf/docs/control-protocol.md) share engine IDs. The control protocol exposes document inspection, node data, input, dialogs, offscreen rendering and screenshots. Transport and path rules differ from PhotoCraft and VectorCraft; one universal socket adapter is not justified.

### DesignCraft

- **Model:** `crates/doc/src/lib.rs` defines spreads/pages, layers/items, stories, styles and swatches; `selection.rs` keeps item/text selections. Coordinates are points (1/72 in), y down, within a spread, unlike the CSS-pixel convention of the proposed SVG output.
- **Commands/transactions:** `crates/engine/src/lib.rs` and `cmd/` define a common `Session::execute`, history and interactions; `crates/tools` emits Begin/Preview/Commit. `crates/ui-egui/src/canvas.rs::Xf` owns view conversion. See the pinned [architecture](https://github.com/storytold/designcraft/blob/7cb8b12507def48fb9346e5004340b5e8e4cfcb7/docs/architecture.md).
- **Render/persistence/export:** stories compose through `crates/compose`; cached composition and render workers avoid doing full layout per UI frame. Native `.designcraft` is a versioned ZIP; exports include PDF, EPUB, HTML and rasters. [images/src/lib.rs](https://github.com/storytold/designcraft/blob/7cb8b12507def48fb9346e5004340b5e8e4cfcb7/crates/images/src/lib.rs) accepts placed SVG, converts CSS pixels to points, rasterizes with resvg on screen and draws SVG vectors into PDF. That is placed-graphic handoff, not editable PaperCraft layers.
- **Automation/accessibility:** `apps/designcraft-cli`, `crates/mcp` and [control protocol](https://github.com/storytold/designcraft/blob/7cb8b12507def48fb9346e5004340b5e8e4cfcb7/docs/control-protocol.md) drive the same engine. Desktop AccessKit is enabled in `apps/designcraft/Cargo.toml`, and custom `WidgetInfo` is present in `crates/ui-egui/src/new_document.rs`; native screen-reader behavior remains untested.

## SVG exchange contract and importer limits

**Observed source:** VectorCraft's [SVG importer](https://github.com/storytold/vectorcraft/blob/cdba0aac03f83bbc633f5e2aa9500354648938d3/crates/svg/src/import.rs) uses usvg with its own text preparation, name/visibility handling and document conversion. Plain rect geometry, corner radius, fill opacity, groups, text/tspan and clip paths have focused tests in `crates/svg/tests/roundtrip.rs`, `import_units.rs` and `options.rs`. Named top-level groups may become layers. IDs and `data-name` supply names; `<title>` alone is not the layer-naming contract.

**Observed source:** FigCraft's [import/mod.rs](https://github.com/storytold/figcraft/blob/d8ff1441b1cd47cb45f1e58b030409ef6f1e24bf/crates/svg/src/import/mod.rs) converts SVG into an editable frame; rectangles remain shapes where possible, clip paths become vector masks, opacity is retained, IDs become names, and external linked files are not read. It imposes element/depth/resource budgets. It explicitly reports clip paths that are themselves clipped by another clip as unsupported. Separate clipped groups are not automatically the same as that unsupported form, so the exported fixture must decide compatibility.

[FigCraft import/text.rs](https://github.com/storytold/figcraft/blob/d8ff1441b1cd47cb45f1e58b030409ef6f1e24bf/crates/svg/src/import/text.rs) groups absolutely positioned `<text>`/`<tspan>` chunks into multiline editable text when font, anchor and baseline pitch agree. Installed/generic font fallback changes metrics. Vertical text, per-glyph rotations and some text-on-path cases are outlined. SVG text has no automatic HTML/egui wrapping contract.

**Implementation decision:** export only the current artboard's background, visible rectangles and text, in paint order, with explicit dimensions/viewBox, bounded corner radii, alpha, XML escaping, text baselines and clipping. Keep `.papercraft` as the editable source. Emit no scripts, `foreignObject`, linked font/image references or proprietary metadata. No native document schema change or conversion is required. Preserve independent text editing where supported, while documenting font substitution, wrapping and clipping differences.

**Inference:** this is a higher-value first exchange than importing a second editor model or adding a general adapter layer: it reuses PaperCraft's current document and atomic export path and has real consumers in the two most relevant tools. PhotoCraft can consume the same SVG through outline/raster fallback, and DesignCraft through placed graphics. These secondary routes remain proposals until exercised.

## Runtime boundary

Installed bundle metadata reports VectorCraft 0.13.1, FigCraft 0.7.0, PhotoCraft 0.10.0, DesignCraft 0.9.0 and ArtCraft Launcher 0.5.1. The bundles contain GUI executables, not standalone CLI executables. Source inventory and executable hashes are retained in ignored `research/private/craft-source/inventory.json`.

**Observed runtime:** the installed VectorCraft and FigCraft GUI executables opened the actual PaperCraft export of `tests/fixtures/svg-exchange.papercraft` through their command-line file argument. Their documented loopback controls returned the imported document trees, offscreen PNGs and real native-window screenshots. This exercised the shipped importers/renderers; no pointer clicks or keyboard input were simulated. Automation roots were confined to the disposable verification directory. No previously open target document was present or modified.
